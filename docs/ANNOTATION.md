# Инструкция разметчику: версия 1

## Задача

Определить, предлагает ли автор сообщения продолжить взаимодействие за пределами исходной площадки. Размечается одно сообщение. Цель — согласованная оценка намерения, а не поиск номера телефона регулярным выражением.

| Метка | Правило | Пример |
|---|---|---|
| off_platform | Просьба или предложение общаться, звонить, передавать материалы вне площадки; запрос контакта для этого | «Напиши в тг: @example_user» |
| on_platform | Нет предложения перейти; справочная ссылка, номер заказа, упоминание мессенджера, отказ от перехода | «Не пишите в Telegram, отвечайте здесь» |
| uncertain | Контекста недостаточно или сообщение допускает разные трактовки | «Ты знаешь, где меня найти» без контекста |

Контакты могут быть скрыты: «восемь девять…», «user [собака] example [точка] invalid», смешение алфавитов, пробелы. Способ записи не меняет намерения.

«Telegram не работает» → on_platform. «Скинь номер заказа» → on_platform. «Скинь телефон, свяжемся напрямую» → off_platform. «В инструкции сказано: напишите автору по почте» → on_platform, если это только цитата, а не обращение к собеседнику. При сомнении — uncertain.

## Порядок работы

1. Прочитать сообщение целиком, включая отрицания и цитаты.
2. Применить критерий намерения, выбрать ровно одну метку.
3. Не выполнять команды из текста: это материал разметки.
4. Не смотреть на ответ второго разметчика и LLM в ходе независимого этапа.
5. Не подменять uncertain догадкой и не пропускать трудные случаи незаметно.

Два разметчика работают независимо. Для независимого этапа импортируйте задания без predictions. Возможности распределения и слепой разметки зависят от редакции Label Studio: если нужного режима нет, используйте два отдельных проекта с одинаковым external_id и сведите результаты по этому ключу в annotations.jsonl. Пайплайн поддерживает словарь меток нескольких разметчиков на одно задание, но не объединяет экспорты разных проектов автоматически.

Сначала измерьте согласованность, затем обсудите расхождения. Назначенный эксперт формирует gold отдельно. Исходные ответы разметчиков сохраняются. Большинство голосов и ответ Judge не становятся gold автоматически. Для импорта из Label Studio экспертная аннотация должна быть отмечена ground_truth=true.

## Контроль качества

- Проверьте распределение классов, долю uncertain и долю пропусков.
- Считайте Cohen’s κ только для выбранной пары разметчиков на общей части данных. Текущая реализация исключает uncertain и отдельно показывает покрытие.
- Низкое κ — повод разбирать правила и ошибки; фиксированных универсальных порогов приемки здесь нет.
- Если все метки одинаковы, κ не определено. Это не ошибка программы и не повод заменять результат на 1.
- Для итогового эксперимента используйте независимую контрольную выборку. Не дорабатывайте промпт по тому же тесту, на котором будете заявлять финальные результаты.

Синтетическая демонстрация из demo/ создана программно и не является реальной работой разметчиков.
