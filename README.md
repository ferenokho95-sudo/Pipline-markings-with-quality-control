# LabelQC — пайплайн разметки с контролем качества на Go

Небольшой CLI-проект: подготовка заданий для Label Studio, импорт ручных аннотаций, LLM-разметка, независимая оценка LLM-as-a-Judge, Cohen’s κ и очередь спорных примеров.

**Весь код пайплайна написан на Go, без сторонних Go-зависимостей.** Label Studio — отдельное приложение: Go-проект обменивается с ним JSON-файлами. Веб-интерфейс Label Studio не переписывается на Go. В архиве нет весов моделей и исполняемых файлов.

Предметная задача — разметка попыток перевести общение за пределы площадки. Рубрика и примеры связаны с проектом детектора обфускации, но пайплайн можно адаптировать под другую номинальную классификацию.

## Быстрый запуск на Windows

1. Установите Go 1.23 или новее: https://go.dev/dl/
2. Распакуйте архив, откройте PowerShell в папке `labelqc-go`.
3. Выполните:

```powershell
go version
go test ./...
go run ./cmd/labelqc demo --out local/my-demo
```

Откройте `local/my-demo/REPORT.md`. Для этой демонстрации не нужны API-ключи, LLM, Python или Label Studio. Примеры и ответы создаются программно: это **проверка пайплайна на синтетических фикстурах**, а не измерение качества реального Judge.

Готовая демонстрация уже находится в `demo/`, копия отчёта — в `reports/demo/`. Повторный запуск не перезаписывает файлы: выбирайте новую папку, например `local/my-demo-2`.

Для Linux/macOS команды такие же. Сборка своего исполняемого файла необязательна:

```bash
go build -buildvcs=false -o labelqc ./cmd/labelqc
```

Windows: `go build -buildvcs=false -o labelqc.exe ./cmd/labelqc`.

## Возможности

- Импорт полного JSON-экспорта Label Studio: ручные метки, отдельный экспертный gold, числовые и объектные completed_by.
- Пропуск отменённых аннотаций, отказ при дублировании ответов одного разметчика или нескольких gold.
- Экспорт заданий и необязательных предварительных предсказаний в Label Studio.
- LLM-разметка и Judge через HTTP API, совместимый с `/v1/chat/completions`, например локальный Ollama.
- Отдельные адреса, модели и API-ключи для разметчика и Judge.
- Версионирование промпта через SHA-256 и привязка ответов к тексту и предложенной метке.
- Согласованность двух людей, совпадение LLM с экспертным эталоном и совпадение Judge с экспертной оценкой корректности.
- Учёт воздержаний, покрытия, матрицы ошибок и очередь для ручной проверки.
- Валидация входных данных, ограничение размера ответа, таймауты, ограниченные повторы HTTP 429/5xx, сохранение частичного результата при ошибке.

## Структура

```text
cmd/labelqc/           CLI и интеграционные тесты
internal/qc/          типы, ввод/вывод, Label Studio, LLM-клиент, метрики и тесты
config/labelstudio.xml интерфейс разметки
docs/ANNOTATION.md    инструкция разметчикам
docs/JUDGE.md         правила Judge и методика оценки
demo/                синтетические задания, метки, ответы Judge и отчёт
reports/demo/        отчёт и очередь проверки демонстрации
.env.example         пример переменных окружения, без секретов
```

## 1. Подготовить сообщения

Файл `local/messages.jsonl`, по одному JSON-объекту на строку:

```json
{"id":"msg-1","text":"Напиши мне в Telegram: @example_user"}
{"id":"msg-2","text":"Не пишите в Telegram, остаёмся в этом чате"}
```

`id` должен быть уникальной непустой строкой, `text` — непустым. Максимальный размер строки JSONL — 4 МиБ. Неизвестные поля отклоняются, чтобы опечатки в схеме не оставались незамеченными.

```bash
go run ./cmd/labelqc prepare --in local/messages.jsonl --out local/tasks.json
```

## 2. Разметить в Label Studio

1. Запустите Label Studio отдельно по официальной инструкции: https://labelstud.io/guide/quick_start
2. Создайте проект и вставьте `config/labelstudio.xml` в настройки Labeling Interface.
3. Импортируйте `local/tasks.json`.
4. Два разметчика независимо назначают метки. Инструкция: `docs/ANNOTATION.md`.
5. Эксперт отдельно разрешает спорные случаи и создаёт эталон. Его аннотация должна иметь `ground_truth=true` в полном экспорте. Автоматического назначения gold по большинству голосов нет.
6. Экспортируйте **JSON**, а не JSON_MIN, и сохраните как `local/labelstudio-export.json`.

```bash
go run ./cmd/labelqc import --in local/labelstudio-export.json --out local/annotations.jsonl
```

`data.external_id` используется как исходный ID. При его отсутствии берётся числовой ID задачи Label Studio. Не меняйте external_id и тексты между экспортами. predictions из Label Studio не считаются ответами человека.

Импорт ожидает `from_name=label`, `to_name=text`, `type=choices`, одну метку из `on_platform`, `off_platform`, `uncertain`. Нерелевантные результаты и отменённые аннотации пропускаются. Повторные ответы одного пользователя нужно разрешить до импорта, иначе программа вернёт ошибку.

Нормализованный формат позволяет собрать данные вручную или из другого источника:

```json
{"id":"msg-1","text":"Напиши мне в Telegram: @example_user","annotations":{"1":"off_platform","2":"off_platform"},"gold":"off_platform"}
```

`gold` необязателен. Без него доступна метрика согласованности людей; сравнения с эталоном будут иметь нулевое покрытие. ID разметчиков — ключи в `annotations`.

## 3. Подключить LLM-разметчик и Judge

Нужен уже запущенный сервер с API `/v1/chat/completions`. Для локального Ollama путь базы — `http://127.0.0.1:11434/v1`. Скачивание и запуск моделей выполняются отдельно, их веса в проект не включены. Имена ниже — шаблоны: замените на доступные у вас модели.

PowerShell:

```powershell
$env:LABELER_BASE_URL = "http://127.0.0.1:11434/v1"
$env:LABELER_MODEL = "your-labeler-model"
$env:JUDGE_BASE_URL = "http://127.0.0.1:11434/v1"
$env:JUDGE_MODEL = "your-judge-model"
```

Bash:

```bash
export LABELER_BASE_URL=http://127.0.0.1:11434/v1
export LABELER_MODEL=your-labeler-model
export JUDGE_BASE_URL=http://127.0.0.1:11434/v1
export JUDGE_MODEL=your-judge-model
```

Если сервер требует ключ, задайте `LABELER_API_KEY` и `JUDGE_API_KEY`. Общий запасной вариант — `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. Приоритет имеют переменные конкретной роли. `.env.example` — образец, автоматически `.env` не загружается. Секреты в запросах не печатаются. Сообщения передаются указанному серверу; используйте данные, которые вправе ему передавать.

```bash
go run ./cmd/labelqc label --in local/messages.jsonl --out local/predictions.jsonl
go run ./cmd/labelqc judge --in local/messages.jsonl --predictions local/predictions.jsonl --out local/judgements.jsonl
```

Judge получает текст и метку кандидата. Экспертный gold и ответы людей не передаются. Предпочтительно выбрать для Judge отдельную модель. Промпты находятся в `internal/qc/llm.go`, методика — в `docs/JUDGE.md`.

Сервер должен вернуть одну завершённую chat completion с `finish_reason=stop`, а её content — обычный JSON без Markdown. Для label: `label` и непустой `reason`; для judge: `verdict` и непустой `reason`. Неизвестные поля, обрезанные ответы и неизвестные метки приводят к ошибке.

Каждый запрос имеет таймаут 90 секунд. HTTP 429 и 5xx повторяются максимум два раза с задержками 1 и 2 секунды. Сетевой сбой с неизвестным исходом не повторяется автоматически. Команды выполняют запросы последовательно.

Если обработка прервалась, уже завершённые строки сохраняются в `<out>.partial.jsonl`. Для продолжения выберите **новый** выходной путь:

```bash
go run ./cmd/labelqc label --in local/messages.jsonl --existing local/predictions.jsonl.partial.jsonl --out local/predictions-retry.jsonl
```

Для judge аналогично. Повторное использование допускается только для тех же текстов, модели, промпта и кандидатов. Частичные ответы не сохраняются при аварийном завершении процесса или отключении питания; это восстановление после обработанной ошибки, а не непрерывный журнал.

Предсказания можно импортировать в Label Studio как предварительные метки:

```bash
go run ./cmd/labelqc prepare --in local/messages.jsonl --predictions local/predictions.jsonl --out local/tasks-with-predictions.json
```

Для оценки независимой ручной разметки используйте задания без предварительных меток, чтобы не подсказывать ответы людям.

## 4. Посчитать метрики

```bash
go run ./cmd/labelqc metrics --in local/annotations.jsonl --predictions local/predictions.jsonl --judgements local/judgements.jsonl --a 1 --b 2 --out local/report-1
```

Результат:

- `report.json` — числа, покрытия, происхождение ответов, матрицы ошибок, hash данных;
- `REPORT.md` — читаемый отчёт;
- `review-queue.json` — ID, тексты и причины для ручной проверки.

Если LLM/Judge ещё не запускались и нужно только κ людей, создайте два пустых файла predictions.jsonl и judgements.jsonl и передайте их теми же флагами. Программа покажет отсутствие предсказаний и нулевое покрытие соответствующих сравнений.

Сначала выбираются записи, где у двух выбранных разметчиков есть определённые метки. Для них:

`κ = (p_observed − p_expected) / (1 − p_expected)`.

Для LLM считается совпадение с независимым экспертным gold. Для Judge экспертная оценка корректности кандидата выводится как `candidate_label == gold`. Проверка Judge не оценивает качество его свободного обоснования.

`uncertain` и пропуски исключаются из условных метрик, но остаются в соответствующих знаменателях покрытия. Показатель `judge_matches_over_all_eligible` дополнительно учитывает пропуски/воздержания как несовпадения. Все доли в JSON — от 0 до 1. Матрицы: строки — эталон/первый разметчик, столбцы — сравниваемая оценка; порядок классов дан в labels.

При отсутствии пар или при одинаковых постоянных метках κ возвращается как JSON null с объяснением в status. Высокое κ не означает правильность меток; высокое совпадение Judge не заменяет проверку покрытия и баланса классов.

На 12 заранее заданных фикстурах:

| Проверка | Результат |
|---|---:|
| κ двух синтетических разметчиков | 0,6667 |
| Совпадение фикстуры LLM с gold | 10/12 = 83,33% |
| Совпадение фикстуры Judge с экспертной оценкой | 9/11 = 81,82% |
| Покрытие Judge | 11/12 = 91,67% |
| Совпадение Judge по всем подходящим примерам | 9/12 = 75% |

**Это заданные тестовые ответы, а не результаты реальной LLM или реальной ручной разметки.** Для резюме подставляйте только результаты собственного независимого эксперимента. В этом проекте реализован и проверен код пайплайна, но реальный провайдер LLM и ваш экземпляр Label Studio в рамках сборки не запускались.

## Проверки

```bash
go test ./...
go vet ./...
```

Есть тесты известных значений κ, вырожденных случаев, покрытия и воздержаний, импорта/экспорта Label Studio, отменённых/повторных аннотаций, устаревших хешей, HTTP-клиента, строгого JSON, отсутствия gold в запросе Judge, полного CLI-цикла и продолжения после ошибки. Сведения о выполненных проверках — `reports/VALIDATION.md`.

Не запускайте две команды, пишущие в один и тот же путь, параллельно. Существующие выходные файлы намеренно не перезаписываются.
